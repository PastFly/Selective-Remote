# Selective Remote

[English](README_EN.md) · **Русский**

[![CI](https://github.com/PastFly/Selective-Remote/actions/workflows/ci.yml/badge.svg)](https://github.com/PastFly/Selective-Remote/actions/workflows/ci.yml)
[![macOS 14+](https://img.shields.io/badge/macOS-14%2B-blue)](https://support.apple.com/macos)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

Нативный клиент удалённого доступа для macOS: RDP с несколькими мониторами,
SSH-терминал, двухпанельный SFTP и SSH-туннели в одном приложении.

Интерфейс доступен на русском и английском языках. По умолчанию приложение
использует язык macOS; отдельный язык можно назначить в **Системные настройки →
Основные → Язык и регион → Приложения**.

## Возможности

- RDP через SDL-FreeRDP, полноэкранный режим на нескольких дисплеях и Retina;
- привычные сочетания macOS: левый Command как Ctrl, правый Command как Windows,
  левый Option как Windows и Fn для переключения языка;
- перенаправление буфера обмена, звука, микрофона, камеры, принтеров и папок;
- встроенный SSH-терминал с локальной историей, поиском, автодополнением и
  каталогом из 300+ общих команд, системные SSH-ключи и локальные/удалённые/Dynamic
  SSH-туннели;
- двухпанельный SFTP с поиском, очередью передач, drag-and-drop, редактором
  POSIX-прав и сохранением подключения между вкладками;
- профили хранятся локально, секреты — в macOS Keychain.

## Установка

Для Apple Silicon (M1 и новее) скачайте готовый DMG из
[последнего GitHub Release](https://github.com/PastFly/Selective-Remote/releases/latest),
откройте его и перетащите **Selective Remote** в `Applications`. Homebrew,
FreeRDP, SDL и исходники пользователю не нужны.

Если DMG собран без сертификата Developer ID, macOS один раз потребует
подтвердить запуск в **Системные настройки → Конфиденциальность и безопасность**.
Подписанный и нотариализованный релиз открывается штатно.

### Сборка из исходников

Требуются macOS 14 или новее, Xcode Command Line Tools и Homebrew:

```bash
brew install freerdp sdl3
git clone https://github.com/PastFly/Selective-Remote.git
cd Selective-Remote
./scripts/build_and_install.sh
```

Скрипт запускает тесты, собирает приложение, сохраняет предыдущую установленную
версию в Корзине и устанавливает `Selective Remote.app` в `/Applications`.

## Обновления

Приложение проверяет канал GitHub при запуске не чаще одного раза в сутки.
Ручная проверка доступна в меню **Selective Remote → Проверить обновления…**.
При наличии новой версии кнопка **Скачать DMG** открывает соответствующий файл
из GitHub Release, а **Что нового** — страницу этого выпуска. Feed публикуется
в `Resources/updates.json`, а описание Release берётся из одноимённого раздела
`CHANGELOG.md`. Технический номер сборки в интерфейсе не показывается.

## Почему камера не работала в 0.7.1

В исходниках были файлы RDPECAM и AVFoundation, но production-сборка намеренно их не компилировала. Переключатель камеры был заблокирован, а в аргументы FreeRDP не добавлялся `/dvc:rdpecam`. Поэтому Windows не получала ни одного видеоустройства, хотя сама RDP-сессия работала.

Начиная с версии 0.8.3 это устранено без возврата опасного глобального перехвата загрузчика: channel addin и AVFoundation HAL собраны в один изолированный модуль `librdpecam-client`, который загружается штатным API FreeRDP.

## Микрофон: условия работы

1. В профиле включите **Микрофон**.
2. Нажмите **Проверить устройства…** и заранее убедитесь, что выбран нужный системный микрофон и доступ разрешён.
3. При первом запросе macOS укажет **Selective Remote** или **Selective Remote Session**. Выберите **Разрешить**.
4. Если доступ ранее был отклонён, окно диагностики откроет раздел **Системные настройки → Конфиденциальность и безопасность → Микрофон**.

## Камера: условия работы

1. Собирайте именно полный `.app`/DMG через `scripts/build_app.sh`; запуск `swift run` не содержит упакованного camera addin.
2. В профиле откройте **Устройства и звук → Камера**, включите перенаправление, выберите источник и качество. Для первой проверки рекомендуется **Встроенная камера Mac** и **Сбалансированное**.
3. Нажмите **Проверить устройства…** и запустите локальный предпросмотр. В строке под ним будет указано фактически открытое устройство и формат.
4. Полностью переподключите RDP: изменение камеры или качества не перестраивает уже активный поток.
5. При первом использовании подтвердите системный запрос. Если доступ ранее отклонён, окно диагностики откроет нужный раздел настроек.
6. На удалённом Windows-компьютере политика **Do not allow video capture redirection** должна быть **Disabled** или **Not configured**:
   `Computer Configuration → Administrative Templates → Windows Components → Remote Desktop Services → Remote Desktop Session Host → Device and Resource Redirection`.
7. После изменения политики выполните `gpupdate /force`, завершите удалённую сессию полностью и подключитесь снова.

В session-логе исправная инициализация содержит строки `Loading Dynamic Virtual Channel rdpecam`, `Selected camera`, `Enumerated 1 selected macOS camera` и `Camera started`.

## Сохранённые возможности

Все возможности RDP сохранены: ручная виртуальная раскладка, сон и hot-plug мониторов, импорт/экспорт без паролей, отдельный Keychain для RD Gateway, поиск и группы, параллельные сессии, направления clipboard, масштаб Windows 100/140/180%, обновления, управление сессиями и переносимый Drag & Drop DMG.

## Оформление

Нажмите кнопку с палитрой рядом с названием Selective Remote в боковой панели или
такую же кнопку над терминалом. В одном окне доступны 14 тем терминала,
пользовательские цвета, шрифт и курсор, а также переключатель прозрачности
всего окна. Ползунок **Непрозрачность** ограничен диапазоном 55–100%, чтобы
элементы управления оставались читаемыми. Все параметры сохраняются
автоматически.

## Первое SSH-подключение

1. Нажмите **+ → Новое SSH**.
2. Укажите hostname или имя `Host` из `~/.ssh/config`, пользователя и порт.
3. Для обычной парольной авторизации оставьте ключ **Автоматически** и нажмите **Открыть SSH** — приложение перейдёт на вкладку **Терминал**, где OpenSSH запросит пароль.
4. Для существующего ключа нажмите **Добавить ключ…** и выберите приватный файл.
5. Для нового ключа нажмите **Создать ключ…**, выберите Ed25519 или RSA 4096 и путь. Passphrase дважды вводится в отдельном встроенном терминале; пустой passphrase допустим. Уже открытая SSH-сессия продолжит работать.
6. Нажмите **Установить на сервер**, подтвердите host key и введите текущий пароль SSH. После успешной установки подключитесь снова уже по ключу.
7. Для SFTP и фоновых туннелей можно оставить аутентифицированную SSH-сессию открытой. Альтернатива — выбрать ключ в профиле: при отсутствии доступного системного агента Selective Remote автоматически запустит собственный и безопасно запросит passphrase.

Selective Remote не копирует импортированный приватный ключ. Созданный ключ записывается системным `ssh-keygen` непосредственно по выбранному пути. В профиле хранится только внутренний идентификатор, имя, путь и fingerprint; файл остаётся под контролем пользователя.

## SFTP

На вкладке **SFTP** нажмите **Подключить SFTP**. Слева отображается локальный
Mac, справа — удалённый сервер. Доступны:

- переход назад/вперёд, вверх, по хлебным крошкам и напрямую по адресу;
- сортировка по имени, размеру, дате, владельцу и правам доступа;
- колонки владельца/группы, POSIX-прав и размера;
- контекстное меню, свойства, переименование и безопасные подтверждения удаления;
- встроенное редактирование удалённых UTF-8-файлов до 5 МБ;
- открытие локальных и временных удалённых копий в выбранном приложении;
- перенос файлов и папок между панелями кнопками или drag-and-drop;
- загрузка файлов и папок из Finder на сервер;
- выгрузка удалённых файлов и папок непосредственно в Finder;
- рекурсивная передача каталогов;
- создание папок на Mac и на сервере.

SFTP работает в `BatchMode` и использует выбранный ключ, системный/резервный
`ssh-agent` либо control socket уже аутентифицированной встроенной SSH-сессии. Для парольного
входа сначала подключитесь во вкладке **Терминал** и оставьте её открытой:
повторно вводить пароль в SFTP не потребуется. Поле **Начальная папка SFTP**
поддерживает `.`, абсолютный путь и путь домашнего каталога, разрешённый
сервером.

## Port Forwarding

На вкладке **Туннели** добавьте один из режимов:

- **Локальный** — порт на Mac перенаправляется к host:port со стороны SSH-сервера;
- **Удалённый** — порт на SSH-сервере перенаправляется к host:port со стороны Mac;
- **SOCKS** — создаётся локальный SOCKS5-прокси.

Туннели запускаются с `BatchMode=yes`, `ExitOnForwardFailure=yes` и keepalive. Изменять активное правило нельзя; сначала остановите его. Remote forwarding зависит от серверных `AllowTcpForwarding` и `GatewayPorts`.

## Честное ограничение без Developer ID

Community-сборка использует ad-hoc подпись либо локальный сертификат Apple Development. Она проверяет собственную целостность, но macOS не может подтвердить личность публичного издателя и notarization выполнить нельзя.

Поэтому на новом Mac пользователь должен **один раз явно разрешить запуск**: после копирования открыть папку **Программы**, щёлкнуть `Selective Remote` правой кнопкой и выбрать **Открыть**. Если macOS всё равно блокирует запуск, используйте **Системные настройки → Конфиденциальность и безопасность → Всё равно открыть**. Глобальные настройки Gatekeeper изменять не нужно.

Полностью обычный первый запуск двойным щелчком без такого подтверждения возможен только после подписи **Developer ID Application** и notarization у Apple. Скрипт уже поддерживает этот путь, если сертификат появится позже.

## Что получает пользователь

В видимой части community DMG находятся только:

- `Selective Remote.app`;
- ярлык `Applications`.

### Установка и переустановка

1. Пользователь открывает DMG.
2. Перетаскивает `Selective Remote` по стрелке на `Applications`.
3. При обновлении выбирает **Заменить**.
4. Извлекает DMG и запускает установленную копию из папки **Программы**.

Перед заменой необходимо закрыть Selective Remote, активные RDP-сессии и SSH-туннели. Профили, журналы и записи Keychain находятся вне `.app`, поэтому при замене не удаляются.

### Удаление

Закройте Selective Remote и переместите `/Applications/Selective Remote.app` в Корзину.

## Архитектуры Mac

Сборка переносима между Mac одной архитектуры:

- Mac с Apple Silicon создаёт `arm64.dmg`;
- Intel Mac создаёт `x86_64.dmg`.

Нельзя выдавать arm64 DMG за Intel-сборку. Если нужны обе платформы, соберите и опубликуйте два DMG с понятными именами. Модели, количество, разрешения и частоты мониторов при этом не зашиты в код.

## Требования только к Mac сборщика

- версия macOS, поддерживаемая установленными Homebrew-библиотеками;
- полный Xcode, выбранный через `xcode-select`;
- Homebrew;
- FreeRDP 3.x и SDL3.

```bash
brew install freerdp
```

XQuartz не нужен: используется SDL-клиент `sdl-freerdp`, а не X11-клиент `xfreerdp`. Все эти зависимости нужны только для создания DMG и вкладываются в готовое приложение.

Эффективный minimum deployment target определяется самой новой вложенной библиотекой. Для локальной тестовой сборки я использовал Homebrew FreeRDP/SDL/FFmpeg, собранные для macOS 26.0, поэтому такой DMG требует **macOS 26.0 или новее**, несмотря на то что собственный Swift-код поддерживает macOS 14. Для выпуска под macOS 14/15 зависимости нужно собирать в совместимом окружении с соответствующим deployment target. Скрипт печатает найденный минимум и записывает его в приложение; macOS проверяет совместимость при запуске.

## Сборка community DMG

На вашем Mac выполните:

```bash
cd ~/Downloads/SelectiveRemote-0.18.0-source
chmod +x scripts/build_app.sh
./scripts/build_app.sh
```

Успешная сборка создаёт:

- `dist/Selective Remote.app`;
- `dist/SelectiveRemote-0.18.0-arm64.dmg`;
- `dist/SelectiveRemote-0.18.0-arm64.dmg.sha256`.

Именно два последних файла можно распространять. Получателю не передаются исходники и не требуется запускать `build_app.sh`.

Скрипт выполняет Swift-тесты, нативный C++-тест interposer, smoke-тест Homebrew-клиента, Release-сборку, генерацию `.icns`, перенос библиотек, переписывание load commands, проверку отсутствия Homebrew-ссылок, подпись вложенного кода, portable smoke-тест и создание DMG.

## Проверка SHA-256

Перед публикацией сохраните строку из файла `.sha256`. Получатель может проверить скачанный DMG:

```bash
cd ~/Downloads
shasum -a 256 SelectiveRemote-0.18.0-arm64.dmg
```

Результат должен полностью совпасть с опубликованным. SHA-256 подтверждает совпадение файла с выложенной вами копией, но не заменяет удостоверение издателя Apple.

## Пароли и Keychain

- RDP и RD Gateway хранятся как две отдельные generic-password записи.
- Keychain читается только после нажатия **Подключиться**.
- Введённый пароль можно использовать один раз без сохранения.
- Пароли не входят в UserDefaults, журналы, `.rdp`, `.selectiveremote`, DMG или список процессов.
- Аргументы и секреты передаются FreeRDP через `/args-from:stdin`.
- пароль SSH-сервера не хранится и запрашивается системным OpenSSH во встроенном PTY;
- passphrase при генерации ключа вводится только во встроенном PTY и не передаётся через аргументы или окружение;
- passphrase приватного ключа обслуживает Apple OpenSSH через `ssh-add --apple-use-keychain`;
- askpass-helper печатает passphrase только в закрытый stdin/stdout-канал `ssh-add`; значение не передаётся в аргументах, окружении или журнале;
- SFTP и фоновые туннели используют системный или запущенный приложением
  `ssh-agent`, либо изолированный control socket активной встроенной SSH-сессии.

Фиксированный путь установки помогает избежать лишних изменений, но ad-hoc подпись не даёт стабильной криптографической личности между разными сборками. После обновления macOS может снова запросить разрешение Keychain. Гарантированно стабильное доверие между релизами требует постоянного сертификата подписи.

## Поддержка разных мониторов

Код не содержит названий конкретных моделей. macOS-дисплей хранится в профиле по UUID CoreGraphics и при запуске сопоставляется с SDL по совокупности признаков:

1. нормализованное имя;
2. логическое и физическое разрешение;
3. признак системного основного дисплея;
4. физический порядок экранов.

Это рассчитано на другие модели, ориентации, частоты и повторяющиеся разрешения. После постоянной замены монитора нажмите **Забыть недоступные** и выберите новый экран. При временном отключении UUID сохраняется, чтобы схема восстановилась после подключения.

## Импорт, сон и несколько сессий

- импортируются `.rdp`, `.selectiveremote` и `.json`;
- экспортируются RDP- и SSH-профили, параметры SFTP и forwarding, всегда без паролей, passphrase и локального ключа;
- выбранный `.rdp` экспортируется только из RDP-профиля;
- перед сном активные дочерние процессы завершаются контролируемо;
- при отключении используемого монитора завершаются только затронутые сессии;
- разные профили могут работать одновременно;
- конкретную или все сессии можно завершить из окна, контекстного меню, меню **Сессия** или строки меню macOS;
- **правый Shift + Enter** переключает полный экран/окно;
- **правый Shift + D** отключает RDP.

## Виртуальная схема мониторов

В автоматическом режиме физически несмежные выбранные дисплеи становятся соседними в Windows. В ручном режиме карточки перетаскиваются с шагом 20 px; основной дисплей нормализуется к `(0, 0)`. Разрешены отрицательные и вертикальные координаты, а перекрытие экранов блокирует запуск.

Interposer меняет только координаты выбранных `rdpMonitor`; системная раскладка macOS и Homebrew-пакеты не модифицируются.

## Диагностика

Кнопка **Журнал** открывает индивидуальный файл RDP-сессии в `~/Library/Application Support/SelectiveRemote/Logs`. У каждого SSH-туннеля есть отдельная кнопка журнала в том же каталоге. Параллельные процессы используют разные имена файлов.

Следующие сообщения сами по себе не означают сбой SelectiveRemote:

- `nsc_init_neon_int: TODO` — FreeRDP использует обычную реализацию NSCodec вместо ещё не реализованной NEON-оптимизации;
- предупреждения `experimental build options` и `runtime-check` описывают параметры сборки установленного Homebrew FreeRDP;
- `self-signed certificate` ожидаем при первом подключении к серверу с самоподписанным сертификатом в режиме TOFU;
- `pthread_setschedprio ... not implemented` означает, что macOS не применила необязательный приоритет потока;
- `ERRCONNECT_CONNECT_CANCELLED` вместе с явным `Connection aborted by user` считается штатным закрытием окна. Без этой строки код означает отменённое подключение и SelectiveRemote покажет диагностическую ошибку.

Строки `[SelectiveRemote Privacy] requesting ...` и `granted ...` означают штатную предварительную проверку. `denied`, `restricted` или `timeout` сопровождаются точной подсказкой в интерфейсе. Старый FreeRDP-маркер `audin_mac_close: not authorized` также распознаётся как отказ в доступе к микрофону.

Успешная инициализация удалённого рабочего стола содержит
`Local framebuffer format` или `Remote framebuffer format`. Для камеры дополнительно
появляются `Registered SelectiveRemote AVFoundation camera backend` и
`Enumerated N macOS camera(s)`.

Полную macOS-сборку необходимо выполнять на Mac: Linux-проверка подтверждает структуру Swift, shell и нативную логику, но не может линковать AppKit, Security, SDL3 и Homebrew FreeRDP и создать настоящий DMG.
